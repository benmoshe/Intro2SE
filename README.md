# Intro2SE
This repository contains the main teaching matirials for the Introduction to OOP OOD course in the School of Computer Science Ariel University. The course focuses on modern Software Engeneering and how to adopt the ever evolving LLM software generating tools to become a super programmer.

Software Engineering: Building Modern Software Systems

Level: Second year CS, Engeneering (undergraduate).
Length: 13 weeks, with two 90-minute sessions and one 2-hour lab each week
Prerequisites: Data structures, one programming language you're comfortable in, basic command line
Method: learn by DOING - this is a Project Based Learning course, it is "IN Class" course (no Zoom).
You are required to phisicaly be in class and present your works.

Course Description

This course covers how professional software is built by teams: turning requirements into designs, writing code that stays maintainable, testing, delivery pipelines, running systems in production, and working with AI coding tools. Most of the course is a semester-long team project run like a real engineering team, with code reviews, sprints, CI/CD, on-call practice and retrospectives.

Learning Outcomes

By the end of the course, students will be able to:

Turn vague stakeholder needs into clear requirements and user stories.
Design modular systems and explain architectural trade-offs in writing (ADRs).
Write clean, tested and reviewable code in a shared codebase.
Build and maintain CI/CD pipelines and deploy to a cloud environment.
Use AI coding tools well: know what to hand them, how to check their output, and where they fail.
Apply secure-by-default practices and reason about threats.
Observe, debug and improve a live system using logs, metrics and traces.
Work well in a team with Git workflows, code review and agile rituals.

AI Policy

AI coding tools such as Claude Code, Copilot and Cursor are allowed and encouraged for the project and labs, with these rules:

You own every line you submit. You must be able to explain any code in your PR.
Disclose AI use in PR descriptions and in the project's AI usage log.
Exams and the week 8 "without AI" lab are AI-free.
AI-generated code gets the same review standard as human code, or stricter.
Tools and Technologies
Version control: Git + GitHub/GitLab
CI/CD: GitHub Actions or GitLab CI
Containers and cloud: Docker; AWS, GCP or Azure (student credits); Terraform
Testing: the language's standard frameworks (pytest, Jest, JUnit), Playwright for E2E
Observability: OpenTelemetry, Grafana/Prometheus or a hosted equivalent
Security: Dependabot/Renovate, Semgrep or CodeQL, secret scanning
Project management: GitHub Projects, Linear or Jira
AI tools: an AI coding assistant or agent of the team's choice

Course Policies
Late work: Each team gets 3 grace days per semester. After that, the penalty is 10% per day.
Peer evaluation: Done at each milestone. It can change individual grades by ±15%.
Academic integrity: Reusing open-source code is fine if you attribute it and respect its license. Copying another team's work is not.
Accessibility: Accommodations are available through the university's disability services office.
